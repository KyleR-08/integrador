⚙️ Technical Manual — Distributed Mail System

Technical reference for the Distributed Mail System. Covers architecture, services, security implementation, deployment, and network infrastructure.

System Overview

The system follows a microservices architecture with two independently containerized services orchestrated via Docker Compose. Both services run on VLAN 10 of the organizational network infrastructure.

Auth Service PythonDockerAES-CBC

Authentication microservice built with FastAPI, SQLModel, and SQLite. Handles user registration and login with AES-CBC password encryption. Runs on port 8000.

Mail Service GoDocker

Email management service built with Go and Gin framework. Supports Gmail and Outlook via OAuth2 (Google API and Microsoft Graph). Serves a web interface on port 8080.

Security Implementation — AES-CBC

The auth service implements AES (Advanced Encryption Standard) in CBC (Cipher Block Chaining) mode for password protection. Passwords are never stored in plain text.

Encryption Flow

1. User submits password → 2. Random 16-byte IV generated → 3. Password padded to AES block size (PKCS7) → 4. AES-CBC encryption using 32-byte key from environment → 5. Result stored as iv_b64:ciphertext_b64

Key Components

Initialization Vector (IV)

A cryptographically random 16-byte value generated per encryption operation using get_random_bytes(16). Ensures identical passwords produce different ciphertexts in the database, providing protection equivalent to salting.

AES Key (Environment Variable)

A 32-byte secret key stored in .env as AES_KEY, never committed to the repository. Functions as a pepper — without it, database contents cannot be decrypted even if stolen.

CBC Mode

Each cipher block is XOR'd with the previous ciphertext block before encryption. The IV initializes the first block. This prevents pattern analysis attacks that would be possible with ECB mode.

Storage Format

database field: encrypted_password
format: {IV_base64}:{ciphertext_base64}
example: aBcDeFgH...==:XyZ123...==

Docker Compose Configuration

services:
  auth-service:
    build: ./auth-service
    ports: ["8000:8000"]
    env_file: ./auth-service/.env

  mail-service:
    build: ./mail-service
    ports: ["8080:8080"]
    volumes:
      - ./mail-service/data:/app/data
      - ./mail-service/token:/app/token
    environment:
      - GIN_MODE=release

Network Infrastructure

Both services run on VLAN 10 (Microservices) — subnet 192.168.0.128/27, gateway 192.168.0.129. Services are accessible at http://192.168.0.130:8000 (auth) and http://192.168.0.130:8080 (mail) from within the network.

Router

Raspberry Pi 3 Model B — OpenWrt 24.10.0

Configured as Router-on-a-Stick with 802.1Q VLAN subinterfaces on eth0. WAN uplink via university WiFi (phy0-sta0, DHCP). LuCI web interface at http://192.168.1.1.
